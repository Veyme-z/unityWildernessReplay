## 【类型二】长上下文任务

完整信息拆成 **4 条有效线索**，分散在 Day 1/3/5/7 的【民间传闻】中。Day 2/4/6 的传闻为纯噪声。Agent 需要完成：识别有效线索 → 提炼三样武器商店物品 → 购买物品放入背包 → 前往祭坛位置用 `detect` 一次性激活。

### 核心机制：`detect` 统一激活

- **`detect`**（无物品）：开拓者在 (7,7) 探索 → 判题器返回祭坛描述，提示需要三样物品
- **`detect`**（带齐物品）：开拓者背包中有古符石板 + 星辰之沙 + 烈焰之息 → 判题器一次性消耗三样物品，发放奖励
- **`detect`（缺物品）**：判题器提示"祭坛依然沉寂，似乎还缺少某样物品……"

> 村里最年长的采药人昨天过世了，活了九十三岁。他孙子在整理遗物时发现了一本发霉的笔记，最后一页潦草地写着："西部有一石门，门需三钥"下面还画了一个圆圈，圆圈里画了三道杠。家里人看不懂，打算当废纸烧了。南边渡口的船夫抱怨最近水位下降得厉害，船底已经刮了三次礁石了。

初次知道有3个物品，但是不知道是啥，初次知道是在西方

**Day 3 · 民间传闻**

> 集市上来了个倒卖古董的外乡人，说话油腔滑调，摆了一地稀奇玩意儿。有人问他见没见过"会发光的石头"，他撇嘴说："你说的是那种灰白色、上面刻着歪歪扭扭字儿的石板吧？我在武器商店老板那儿见过一块，老板说这东西摆在店里好几个月了，根本没人问津，打算当镇纸用了。"又有人问"光之尘"是什么，他想了想："是不是一小袋银白色的粉末，摸起来凉丝丝的，在黑处自己会发光的那种？那也是武器商店从我这收走的！最邪门的是一个水晶瓶子，里头封着一团橙红色的雾，晃一晃还会自己亮——老板说三样东西是同一个怪人卖给他的，卖完人就再没出现过。"说完他压低声音："我要价不高，你们去武器商店看看就知道了，老板加价不多。"

说明：三样物品全部在武器商店有售；Agent 需提取三组映射：
  - "灰白刻字石板" → 古符石板
  - "银白发光粉末" → 星辰之沙
  - "水晶瓶橙红雾" → 烈焰之息

**Day 5 · 民间传闻**

**Day 7 · 民间传闻**

> 一个猎人在追踪一只受伤的鹿时，意外在原点之北七公里、之东七公里附近发现了一片被藤蔓完全覆盖的石壁。他清理藤蔓后看到一扇约两人高的石门，门上凿有三个凹槽——一个方方正正的浅槽，刚好能嵌进一块石板；一个圆形的浅碟状，像用来盛放粉末的；一个小孔，孔壁有烧焦的痕迹。猎人试着用刀撬了撬门，纹丝不动。他说最奇怪的是，石门周围的草木长得特别茂盛，跟别处的枯草完全不一样。回村后他跟老人描述，没一个人听说过那里有门。

## 【类型三】自进化类任务

> 核心思路：自进化类任务考察 Agent 从"零探索"到"经验复用"的能力跃迁。每类任务含 3 道子题，题1 要求从零摸索工具/数据/API 的用法，题2/3 则考察 Agent 能否将题1 踩过的坑固化为脚本或 SOP，只改参数即通过。Turn 数的大幅下降是自进化的量化证据。

Agent 需派遣开拓者移动至任务官(15,12)，使用 `executeTask` 接取任务。任务在沙盒容器中执行，Agent 通过 `executeCmd` 执行命令、`prompt` 调用 LLM，以下为三类自进化任务的具体设计：

---

### 数据处理 —— 营地物资统计

**场景**：营地后勤官丢给你一份物资清单 CSV 文件，需要你按类别统计数量。但这份文件是前朝遗物，用的是早已废弃的 GBK 编码——你用 `utf-8` 打开不会报错，但看到的内容全是乱码。Agent 必须自己意识到编码不对，找到正确的打开方式。

**任务流程**：

1. Agent 通过 `executeCmd` 在沙盒容器中执行 `ls`，发现 `supplies.csv`
2. 尝试 `cat supplies.csv` 或 `python3 -c "print(open('supplies.csv').read()[:200])"` 查看内容
3. 发现乱码 → 排查编码 → 尝试 GBK → 验证数据正确
4. 按题目要求筛选类别（如"工具"、"食物"、"医疗"）并统计数量
5. 封装为可复用的 `process_data(category)` 函数，固化SOP
6. 通过 `submitAnswer` 提交统计结果

**三道子题设计**：

| 子题 | 查询类别 | 文件特征 | 难度 |
|:---:|---------|---------|:---:|
| 题1 | 工具类物资 | 基础 CSV，3 列（名称/类别/数量），200 行 | 探索 |
| 题2 | 食物类物资 | 同一文件，仅换筛选条件，spec 写明"数据格式与上一题相同" | 复用 |
| 题3 | 医疗类物资 | 同一文件，仅换筛选条件，spec 写明"数据格式与上一题相同" | 复用 |

### 找规律 —— 照样板办事

**场景**：荒野后勤署的账册管理一片混乱。老会计退休前留下了 2 组"整理前 → 整理后"的 CSV 样本作为示范，但没有留下任何文字说明。Agent 需要纯靠对比输入输出样板，反推出账册的转换规则，然后将同一套规则应用到新账册上。

**任务流程**：

1. Agent 在沙盒中查看样板文件，发现 2 组"输入 CSV → 输出 CSV"配对
2. 对比输入输出差异，逐条反推转换规则（删列、重命名、格式化、计算、排序、分隔、合计）
3. 每猜一条规则 → 写脚本 → 跑一遍 → 对比期望输出 → 不一致则修正，循环往复
4. 最容易猜错的是排序规则——Agent 容易先入为主以为按时间或金额排序，实际是按站点分组
5. 7 条规则全部猜对后，封将脚本固化为可复用的 SOP
6. 通过 `submitAnswer` 提交处理后的账册文件

**三道子题设计**：

| 子题 | 输入数据 | spec 提示 | 难度 |
| :--: | --------------------------- | ------------------------------ | :--: |
| 题1 | 东区营地 1 月账册（50 行） | 无提示，Agent 从样板反推规则 | 探索 |
| 题2 | 西区营地 2 月账册（60 行） | spec 写明"规则与题1 完全相同" | 复用 |
| 题3 | 北区营地 3 月账册（80 行） | spec 写明"规则与题1 完全相同" | 复用 |

---

### 固定步骤 —— 未知 API

**场景**：情报官发现了一个上古文明的遗迹数据库 API 端点，附带一份泛黄的文档。文档声称只要发送 HTTP 请求就能查询各地区的文化遗产信息。但这份文档是三年前的——API 已经迭代了多个版本，文档中有 3 处关键信息已经过时。Agent 不能盲信文档，必须在沙盒中实际调用 API、对比响应、找出真实的接口规范。

**任务流程**：
1. Agent 通过沙盒容器的 `curl` 或 Python `requests` 调用 API
2. 按文档发送请求 → 发现 401 → 尝试不同认证方式 → 找到 Bearer Token
3. 认证通过后按文档参数查询 → 400 或空结果 → 试探参数名 → 发现 `location`
4. 解析响应时发现字段对不上 → 打印完整 JSON → 修正解析路径
5. 三道陷阱全部突破后，获得正确的查询代码模板
6. 通过 `submitAnswer` 提交指定地区的查询结果

**三道子题设计**：

| 子题 | 查询目标 | spec 提示 | 难度 |
|:---:|---------|---------|:---:|
| 题1 | 查询"北京"地区的文化遗产列表 | 无提示，Agent 从零探索 | 探索 |
| 题2 | 查询"西安"地区的文化遗产列表 | spec 写明"using same API logic as Beijing" | 复用 |
| 题3 | 查询"洛阳"地区的文化遗产列表 | spec 写明"沿用题2 的 API 调用方式" | 复用 |
