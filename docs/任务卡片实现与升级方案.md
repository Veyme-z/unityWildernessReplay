## 一、当前实现（Phase 1 无素材版）

### 1. 文件清单

| 文件 | 职责 |
|------|------|
| `Assets/Scripts/FX/TaskCardBadge.cs` | 单张任务卡片：程序化 Quad 底板 + TextMesh 文字，4 态动画/暂停冻结/Billboard/淡出销毁 |
| `Assets/Scripts/FX/TaskBadgeManager.cs` | 全局管理器（挂在 ReplayEntry 的 GO，随 `DontDestroyOnLoad`）：每帧从数据快照判定每个队伍开拓者头顶卡片的创建/更新/销毁 |
| `Assets/Scripts/ReplayEntry.cs` | 仅加一行 `gameObject.AddComponent<TaskBadgeManager>()` |

**硬约束（永久保留）**：不修改 `Core/`、`Scene/`（含 UnitView）、`UI/`、已有 `FX/`（TradeBadge/FxFactory）任何文件；不修改 `.prefab/.unity/.meta`；不用第三方库；不用 StreamingAssets 播放视频（Phase 2 才引入，见下）。

### 2. 卡片 4 态

| 状态 | 表现 | 触发 |
|------|------|------|
| `Intro` | 灰色底板「接受任务」 | 队伍有任务且 `roundCost == 0`（刚接任务那回合） |
| `Working` | 蓝色「破解中…」（点号 0.5s 循环） | 有任务未完成（稳态） |
| `Success` | 绿色「✓ 通过」（弹跳 0.3s） | **上一回合**有任务未完成、**本回合** `isTaskComplete=true` |
| `Fail` | 红色「× 失败」（抖动 0.5s） | **上一回合**有任务未完成、**本回合**任务消失且未完成（超时/移除） |

- Success/Fail 结果卡片展示 1.5s 后淡出（0.2s）销毁；播放中不受稳态 Hidden 打断，只有新任务（Intro/Working）可打断。
- 无任务时（稳态）不创建卡片（Hidden 不渲染）。

### 3. 数据驱动设计（关键）

**不监听 `executeTask` / `submitAnswer` 命令事件**，而是按"数据回合"做**跳变检测**：

- 数据源：`player.data.rounds[cur-1].teams[].task`（原始快照，含 `taskType`/`isTaskComplete`/`roundCost`；StateEngine 的 teams 是 TeamStat 字典，不含原始 task，故直接读 replay 数据）。
- `task` 的 `pos != null`（无任务时为 null）在 C# 模型里用「`taskType` 非空」作等价代理。
- **跳变读 `rounds[cur-2]`（数据里的上一回合），不存上一帧快照** —— 拖动进度条/JumpTo 到任意回合时按目标回合数据重建，不会把"任务在别的回合消失"误判成"当前回合失败"（这是旧实现 Seek 后开拓者站着也弹失败框的根因，见第五节）。

### 4. 状态判定（`DecideState`）

```
成功: prev.hasPos && !prev.isComplete && cur.isComplete
失败: prev.hasPos && !prev.isComplete && !cur.hasPos && !cur.isComplete
稳态无任务:                       → Hidden
稳态有任务 roundCost==0:          → Intro
稳态有任务未完成:                 → Working
已完成任务的稳态（Success 已触发）→ Hidden
```

### 5. Seek / 拖动进度条处理（bug 根治）

- **Seek 唯一可靠信号**：`!_player.playing && _player.cur != _lastCur`。
  - `PlaybackControlPanelController.OnDrag` 是先 `SetPlaying(false)` 再 `JumpTo`；而正常播放走 `ReplayPlayer` 的 `while(_acc>=RoundDur)` 循环，快进时 `cur` 也能一帧连跳多回合（此时 `playing=true`）。所以**不能用 `|cur-lastCur|>1`** 判 Seek（会误清播放中的卡片），必须用"暂停 && cur 变了"。
- 检测到 Seek：`ClearAllBadges()` **先全清**，再由下方 team loop 按目标回合数据重建。
- **必须清空的根因**：结果卡片（Success/Fail）在暂停时 `Update` 提前 return，1.5s 结束计时被冻结、**永不淡出销毁**；若不清空，开拓者已回到任务官前站着（无任务）时，残留的失败框会一直挂着。

### 6. 定位 / 缩放

- 锚点世界坐标 `CardAnchorWorld(parent)`：以开拓者 `HpFill` 血条世界中心为基准，`血条Y + HP_CLEARANCE(0.5) + 底板世界半高` —— 卡片底沿在世界空间**精确高于血条 0.5**，不受父节点 Scale 影响。
- `CARD_SCALE = 2f`：底板/文字/偏移全部 ×2（画面放大 2 倍）。

### 7. 暂停冻结

`TaskCardBadge.Update` 开头 `if (_player != null && !_player.playing) return;` —— Working 点循环 / Success 弹跳 / Fail 抖动 / 淡入淡出全部暂停；Billboard（`LateUpdate` 面向相机）不受暂停影响。

### 8. 性能

- 底板共享一个 `Sprites/Default` 材质 + `MaterialPropertyBlock` 改色 + `enableInstancing=true` → 所有卡片 Quad 走 GPU Instancing 批。
- WebGL 中文 TextMesh 防隐形：`font.RequestCharactersInTexture(text, fontSize, fontStyle)` 预热字形 + `MeshRenderer.sharedMaterial = font.material` 同步材质（与 TradeBadge 同一套处理，字体统一 `UiFonts.Get()`）。
- `Working` 点号用缓存避免每帧重建字符串。

## 二、Phase 2 升级方案（图片/视频替换，未实现）

### 1. 升级目标

把程序化纯色底板换成真实素材：
- **Intro**（接受任务）：静态**图片**
- **Working / Success / Fail**：动态**视频**

对外接口（`SetState(state, taskType)` / `IsFinished` / `CurrentState`）保持不变，只替换内部"渲染层"。

### 2. 素材目录与命名

```
Assets/StreamingAssets/
├── TaskImages/
│   └── {taskType}_intro.png          # Intro 用图
└── TaskVideos/
    └── {taskType}_{stage}.mp4        # stage = working / success / fail
```

`taskType` 为任务类型字符串（当前 replay 里只有 `"自进化类"` 与 `""`），未匹配到素材时回退 `"generic"`（`_taskType` 字段已在 TaskCardBadge 预留，默认 `"generic"`）。替换素材只需往这两个目录丢文件，**不改代码**（前提是映射表里没有自定义 taskType 需要加前缀规则）。

### 3. 技术路线

| 状态 | 渲染层方案 |
|------|-----------|
| Intro | 底板 Quad 的 `material.mainTexture` ← `UnityWebRequestTexture` 异步加载的 png（StreamingAssets 在 WebGL 必须走 UnityWebRequest） |
| Working / Success / Fail | 底板 Quad 的 `material.mainTexture` ← **RenderTexture** ← **VideoPlayer**（`Prepare`→`Play`，播放指定 `{taskType}_{stage}.mp4`） |

注意：Stage 内**不得修改 .prefab/.unity/.meta**；VideoPlayer 与 RenderTexture 均由代码 `AddComponent`/`new RenderTexture` 创建，运行时挂到 `Bg` Quad 上。

### 4. 具体改造点（都集中在 `TaskCardBadge.cs`）

1. `ApplyStateVisuals(state)` 里，按 state 切换底板贴图来源（Intro→png；Working/Success/Fail→对应视频）。
2. 视频播放控制：`SwitchTo(state)` 时 `Stop()` 旧视频、加载播放新视频；Success/Fail 播完（`_elapsed >= RESULT_DURATION`）淡出销毁时 `Stop()` 释放。
3. 暂停冻结：`_player.playing == false` 时 `videoPlayer.Pause()`，恢复时 `Play()`。
4. 资源缓存与释放：每 taskType 一个 `RenderTexture`（可复用），销毁卡片时 `OnDestroy` 释放视频/贴图引用，避免内存泄漏。
5. `_taskType` 前缀映射表：`taskType → 素材文件名前缀`，未命中默认 `"generic"`。

### 5. 边界（Phase 2 不做 / 不允许）

- 不碰 `Core/`、`Scene/`、`UI/`、`ReplayEntry` 已有逻辑；不碰 .prefab/.unity/.meta。
- 不引入第三方插件，VideoPlayer 用内置 `UnityEngine.Video.VideoPlayer`。
- 素材缺失必须优雅降级：加载失败 → 回退当前程序化纯色版（不崩、有 Warning）。

## 三、数据现状说明（2026-08-21 排查结论）

> 换数据前先读这段，避免以为"新版要改解析"。

### 1. 新版 replay.txt（1010 回合）vs 旧版 replay_906.txt：**零字段差异**

- 75 个 JSON 键集合完全一致，无新增/删除字段；行结构变体一致；枚举值集一致。
- **解析器 / 任务卡片逻辑对新版完全适用，无需任何改动。**
- 真实差异全在**值**层面（另一局对战）：
  - 回合 1010 vs 906；战斗更多（attack 9447 vs 8187）。
  - **敌方单位数值全面加强**：blackBear 攻击 5→20、skeletonMage 10→40、deathWarrior 20→70、cavalry 40→120（血量同步上调）—— 这就是"怪物变强"，**不是防御塔升级**。
  - 防御塔 `tower` 定义两版一致（health 1000 / attackPower 20），**没有"给防御塔升级的道具"**（物品全集与 action 全集两版均无此物）。
  - 攻击命令 `targetPos` 两版都是**单个坐标**；AOE 道具（新版 DizzyWeapon / 旧版 Bomb）的 `skillTargetPos` **一直是数组**，非新版新增。均不影响解析。
  - 物品集合：新版无 `iron`/`Bomb`，改用 `DizzyWeapon` + `Medicine` 组合。

### 2. 任务数据现状

- `task.taskType` 值域只有 `""`（无任务）与 `"自进化类"`。
- 任务描述**仍是占位**（右侧任务面板显示硬编码假新闻，与 replay 任务零关联）；所有任务靠**超时失败**（`submitAnswer` 0 次、`executeTask` 6 次），没有真实完成路径。
- 若要做"真实任务文案/描述"（Phase 3 可选），需在任务系统侧输出描述字段并同步到 `TaskPanelController`，当前无此数据。
