### 2. 卡片 4 态

| 状态 | 表现 | 触发 |
|------|------|------|
| `Intro` | **task.png 图片底板**（图片自带「接受任务」字样，不叠文字；有金黄描边；**至少展示 2 回合**） | 队伍有任务且 `roundCost == 0`（刚接任务那回合）；数据切 Working 后若未满 2 回合仍停留 Intro |
| `Working` | 蓝色「破解中…」（点号 0.5s 循环） | 有任务未完成（稳态） |
| `Success` | 绿色「✓ 通过」（弹跳 0.3s） | **上一回合**有任务未完成、**本回合** `isTaskComplete=true` |
| `Fail` | 红色「× 失败」（抖动 0.5s） | **上一回合**有任务未完成、**本回合**任务消失且未完成（超时/移除） |

- Success/Fail 结果卡片展示 1.5s 后淡出（0.2s）销毁；播放中不受稳态 Hidden 打断，只有新任务（Intro/Working）可打断。
- 无任务时（稳态）不创建卡片（Hidden 不渲染）。
- **Intro 至少展示 2 回合**（2026-08-24）：数据上 `roundCost==0` 仅接任务那 1 回合，图片会一闪而过 → 卡片 `SwitchTo(Intro)` 时记录 `_introStartCur`，`SetState` 里若当前 Intro、数据已切 Working 但 `player.cur - _introStartCur < INTRO_MIN_ROUNDS(2)` 则**延迟切换**继续展示图片；满 2 回合才进 Working。结果态（Success/Fail）不受延迟、可立即打断；Seek/跳回合按新回合数据即时生效（重建时 `_introStartCur` 同步为当前回合）。
- **Intro 图片不叠文字**（2026-08-24）：task.png 自带「接受任务」字样 → `ApplyStateVisuals` 里 Intro 状态隐藏文字对象（`_txtGo.SetActive(false)`），其余状态显示；避免图片上再叠一遍字。

### 3. 数据驱动设计（关键）

**不监听 `executeTask` / `submitAnswer` 命令事件**，而是按"数据回合"做**跳变检测**：

- 数据源：`player.data.rounds[cur-1].teams[].task`（原始快照，含 `taskType`/`isTaskComplete`/`roundCost`；StateEngine 的 teams 是 TeamStat 字典，不含原始 task，故直接读 replay 数据）。
- `task` 的 `pos != null`（无任务时为 null）在 C# 模型里用「`taskType` 非空」作等价代理。
- **跳变读 `rounds[cur-2]`（数据里的上一回合），不存上一帧快照** —— 拖动进度条/JumpTo 到任意回合时按目标回合数据重建，不会把"任务在别的回合消失"误判成"当前回合失败"（这是旧实现 Seek 后开拓者站着也弹失败框的根因，见第五节）。

### 4. 状态判定（`DecideState`）

```
成功: prev.hasPos && !prev.isComplete && cur.isComplete
失败: prev.hasPos && !prev.isComplete && !cur.hasPos && !cur.isComplete
稳态无任务:                       → Hidden
稳态有任务 roundCost==0:          → Intro
稳态有任务未完成:                 → Working
已完成任务的稳态（Success 已触发）→ Hidden
```

### 5. Seek / 拖动进度条处理（bug 根治）

- **Seek 唯一可靠信号**：`!_player.playing && _player.cur != _lastCur`。
  - `PlaybackControlPanelController.OnDrag` 是先 `SetPlaying(false)` 再 `JumpTo`；而正常播放走 `ReplayPlayer` 的 `while(_acc>=RoundDur)` 循环，快进时 `cur` 也能一帧连跳多回合（此时 `playing=true`）。所以**不能用 `|cur-lastCur|>1`** 判 Seek（会误清播放中的卡片），必须用"暂停 && cur 变了"。
- 检测到 Seek：`ClearAllBadges()` **先全清**，再由下方 team loop 按目标回合数据重建。
- **必须清空的根因**：结果卡片（Success/Fail）在暂停时 `Update` 提前 return，1.5s 结束计时被冻结、**永不淡出销毁**；若不清空，开拓者已回到任务官前站着（无任务）时，残留的失败框会一直挂着。

### 6. 定位 / 缩放

- 锚点世界坐标 `CardAnchorWorld(parent)`：以开拓者 `HpFill` 血条世界中心为基准，`血条Y + HP_CLEARANCE(0.5) + 底板世界半高` —— 卡片底沿在世界空间**精确高于血条 0.5**，不受父节点 Scale 影响。
- `CARD_SCALE = 2f`：底板/文字/偏移全部 ×2（画面放大 2 倍）。

### 7. 暂停冻结

`TaskCardBadge.Update` 开头 `if (_player != null && !_player.playing) return;` —— Working 点循环 / Success 弹跳 / Fail 抖动 / 淡入淡出全部暂停；Billboard（`LateUpdate` 面向相机）不受暂停影响。

### 8. 性能

- 底板共享一个 `Sprites/Default` 材质 + `MaterialPropertyBlock` 改色 + `enableInstancing=true` → 所有卡片 Quad 走 GPU Instancing 批。
- WebGL 中文 TextMesh 防隐形：`font.RequestCharactersInTexture(text, fontSize, fontStyle)` 预热字形 + `MeshRenderer.sharedMaterial = font.material` 同步材质（与 TradeBadge 同一套处理，字体统一 `UiFonts.Get()`）。
- `Working` 点号用缓存避免每帧重建字符串。

### 2. 素材目录与命名（已定稿）

```
Assets/Resources/Sprites/task.png        # Intro 图片 ✅ 已实现
Assets/StreamingAssets/TaskVideos/       # 视频
├── working.mp4      # Working 状态（破解中）✅ 已实现
├── success.mp4      # Success 状态（✓ 通过）✅ 已实现（2026-08-24，1280×720，约 3.4s）
```

- **图片放 `Resources/`**（与项目所有 UI 图片一致，`Resources.Load<Texture2D>("Sprites/task")` 同步加载、打包进 Build、WebGL 可用；缺图回退纯色版不崩）。命名 `task` 即当前 Intro 唯一图，将来多种任务类型再按 `{taskType}_intro` 加图。
- **视频放 `StreamingAssets/TaskVideos/`**（VideoPlayer 直接读文件路径；WebGL 用 `WorkingVideoUrl()` 把 StreamingAssets 归一化成**相对当前网页的 URL**，剥掉 `http(s)://host` 前缀防协议混用，浏览器视频元素直接相对解析）。当前只有一种任务类型 `"自进化类"`，**直接用 `stage` 名**（working/success/fail）；将来出现多种任务类型再改成 `{taskType}_{stage}.mp4`（代码按 `_taskType` 拼前缀，未命中回退 `"generic"`，映射表已预留）。

### 3. 技术路线

| 状态 | 渲染层方案 |
|------|-----------|
| Intro | 底板 Quad 的 MPB `_MainTex` ← `Resources.Load<Texture2D>("Sprites/task")`（已实现，见 `IntroTex()` / `SetMainTexture()`） |
| Working | 底板 Quad 的 MPB `_MainTex` ← **RenderTexture** ← **VideoPlayer**（`Prepare`→`Play`，播放 working.mp4，循环 + 暂停冻结）✅ 已实现 |
| Success / Fail | 底板 Quad 的 MPB `_MainTex` ← **RenderTexture** ← **VideoPlayer**（success.mp4 / fail.mp4，循环 + 播完淡出销毁；加载失败降级纯色+文字）✅ 已实现 |

注意：VideoPlayer 与 RenderTexture 均由代码 `AddComponent`/`new RenderTexture` 创建，运行时挂到卡片上；不碰 .prefab/.unity/.meta。WebGL 用 HTML5 video 元素，URL 走相对路径（见 `WorkingVideoUrl()`）。

> **⚠ 图片阶段踩过的坑（2026-08-24 修复，视频阶段沿用）**：`MaterialPropertyBlock.SetTexture(name, null)` **会抛 `ArgumentNullException`**（参数名 `value`），且没有单属性清除 API。因此从 Intro（有图）切到其余状态（无图）时，**不能** `_mpb.SetTexture("_MainTex", null)` —— 异常中断导致 `_MainTex` 从未清除，Working 底板一直残留 Intro 图片（表现：接受任务后底图还是那张 png）。正确做法是 `_mpb.Clear()` 清空全部属性后再按需 `SetTexture`。
> **金黄描边**：Awake 建一个比底板大 `BORDER=0.05`（卡片单位）的 Border Quad 垫在 Bg 之后，MPB `_Color`=0xFFD700 金黄，让卡片在草地/图片背景上轮廓清晰（用户反馈"图片和地图都是绿色看不见"）。所有状态（含图片 Intro）均保留描边。
> **⚠ 视频阶段踩过的坑（2026-08-24 修复）**：
> 1. **暂停时视频底图全透明**：`OnVideoPrepared` 是**异步回调**，回调里 `SetMainTexture(_vpRT)` 会 `_mpb.Clear()` 清掉全部属性（含 `_Color`），而 `ApplyAlpha(1f)` 在回调**之前**已执行；暂停时 `Update` 提前 return 不再跑 `ApplyAlpha` → `_Color` 缺失 = 全透明，视频底图不可见。修复：`SetMainTexture` 里 `Clear()` 后**立即补回 `_Color`**（`_stateColor`），不再依赖 ApplyAlpha 兜底。
> 2. **Working 视频模式下文字对象误激活**：`showText` 原在 switch **之前**计算，此时 `_videoWorking` 还是 false → 视频态下文字被 SetActive(true)（空文本不显示但不干净）。修复：把 `_txtGo.SetActive(showText)` 移到 switch **之后**按最终 `_videoWorking` 判定。
> 3. **Intro→Working 过渡残留图片**（旧方案）：视频准备就绪前底板残留 Intro 图。**已被"无中间态"方案取代**（见 #6）：现在故意保留 Intro 图直到视频就绪，不再清成纯色，也就不存在"图片/视频并存"的中间帧。
> 4. **图片→视频之间白色空白闪帧**（旧方案）：`_stateColor` 提前转白 + 视频未挂上 = 纯白 Quad 闪帧。第一版修复是"等待期保持纯蓝"。**已被 #6 的"无中间态"方案彻底取代**：Working 未就绪时底板保持 Intro 图片（白 tint 图片，不是蓝也不是空贴图白底），视频就绪瞬间无缝接管——无论蓝或白，等待期都不再出现。
> 5. **Working 视频循环（时长跟回合走）**：working.mp4 时长 4s，Working 阶段可能跨越很多回合 → 必须循环。三重保障：① `isLooping=true`（主循环）；② `loopPointReached` 事件 `OnVideoLoop` 兜底（个别平台 isLooping 失效时在结尾处回到开头）；③ `TryPlayVideo` 里未在播放且未暂停时 `_vp.time=0` 后 `Play()`（Update 每帧兜底重启）。暂停时视频冻结、恢复后继续，循环不因暂停断档。
> 6. **Intro→Working 无中间态切换（2026-08-24 终极方案，取代 #3/#4）**：用户要求"图片后面直接接视频，不要蓝/白加载态"。两条腿：① **Intro 接任务即后台预载视频**（`StartVideoPreload` → `EnsureVideoPlayer` + `Prepare()`，不显示不播放；`OnVideoPrepared` 里静默预卷开播进 RT，为 Working 蓄帧）——Working 到来时视频大概率已就绪，`BeginWorkingVideo` 直接把底板 `_MainTex` 换成视频 RT，`_stateColor` 全程白，零等待。② **万一未就绪**（如直接 Seek 进 Working）：保持 Intro 图片（白 tint），`OnVideoPrepared` 就绪瞬间无缝接管——**不出现纯蓝、不出现空贴图白底**。Intro 与 Working 的 `_stateColor` 全程保持白（图片/视频都是 tex×白），切换只是换 `_MainTex` 引用，无任何颜色中间态。`TryPlayVideo` 加 `_videoPrepared` 守卫，未就绪不空转。
> 7. **Success/Fail 视频多 slot 无中间态（2026-08-24，结果态，取代旧纯色+文字）**：渲染层从单 `_vp/_vpRT` 重构为**多 slot**——`_videos` 字典按 url 缓存 working/success/fail 三路独立 `VideoPlayer + RenderTexture`（`VideoSlot`：url/player/rt/prepared/failed）。**Intro 接任务即 `StartVideoPreload()` 对三个视频全部 `Prepare()`**（只准备不解码，代价极小）：working 在 Intro 阶段预卷蓄帧（Working 直接接视频）、success/fail 仅就绪备用。进入 Success/Fail：`BeginResultVideo(url)` 就绪即 `PlayVideo(slot)`（**不可见开播**，Update 里渲染出帧 `frame>=1` 瞬间换底板 `_MainTex`）；未就绪→**保持当前画面（working 视频 / Intro 图）不动**——与 #6 同一原则，**绝不蓝/白/空底**。结果视频 `isLooping=true` 循环，`_resultDuration = max(RESULT_DURATION=1.5, 视频时长+0.1)` 保证**看完一遍再淡出销毁**；已显示的 slot 保证播放、其余 slot 停播（结果接管后 working 停掉）。`OnVideoPrepared` 只标记就绪+绑定 RT，**不做任何自动开播/换贴图**（避免"就绪即抢底板"破坏当前画面，显示完全由 Update 按状态驱动）。`OnVideoError` 按当前状态降级纯色+文字（Working 蓝"破解中"/Success 绿"✓ 通过"/Fail 红"× 失败"）。**暂停冻结**：Update 顶部 `paused` 时对所有正在播放的 slot 逐个 `Pause()`，恢复由 PlayVideo 续播。

### 4. 具体改造点（视频阶段，都集中在 `TaskCardBadge.cs`）

1. ✅ `ApplyStateVisuals(state)` 按 state 切换底板贴图来源（Intro=图、Working=working 视频、Success/Fail=success/fail 视频；目标视频未就绪保持当前画面无中间态；加载失败降级纯色+文字）。
2. ✅ 视频播放控制：`EnsureVideo()`（每 url 创建/配置一次 VideoPlayer slot，working/success/fail 三路）＋`StartVideoPreload()`（Intro 对全部视频 `Prepare()` 预载）＋`BeginWorkingVideo()`（Working 上视频/未就绪保持图片）＋`BeginResultVideo(url)`（Success/Fail 上结果视频/未就绪保持当前画面）＋`PlayVideo(slot)`（暂停冻结续播/播完回开头循环）＋`TargetDisplayUrl()`/`FindSlot()`；`OnDestroy` 遍历 `_videos` 逐个停止/解绑/Release RT。
3. ✅ 暂停冻结：`Update` 顶部 `paused` 时对所有正在播放的 slot `Pause()`，恢复时 `PlayVideo()`（`_player.playing` 驱动）；**视频循环**（`isLooping` + `loopPointReached` 兜底 + `PlayVideo` 播完回开头重播）让显示时长跟回合走；`PlayVideo` 加 `prepared`/`failed` 守卫，未就绪不干预播放、避免准备期空转。
4. ✅ 资源释放：`OnDestroy` 遍历 `_videos` 停 VideoPlayer、解绑事件、Release RenderTexture，防泄漏。
5. ⏳ `_taskType` 前缀映射表：当前仅 `working.mp4`/`success.mp4`/`fail.mp4` 三个常量；将来多任务类型再按 `{taskType}_{stage}.mp4` 拼（未命中回退 `"generic"`，映射表已预留）。
6. ✅ 优雅降级：`OnVideoError` → 按当前状态回退纯色 + 文字（Working 蓝"破解中"/Success 绿"✓ 通过"/Fail 红"× 失败"），不崩、打 Warning。

### 5. 边界（不允许）

- 不碰 `Core/`、`Scene/`、`UI/`、`ReplayEntry` 已有逻辑；不碰 .prefab/.unity/.meta。
- 不引入第三方插件，VideoPlayer 用内置 `UnityEngine.Video.VideoPlayer`。
- 素材缺失必须优雅降级：加载失败 → 回退当前程序化纯色版（不崩、有 Warning）。
