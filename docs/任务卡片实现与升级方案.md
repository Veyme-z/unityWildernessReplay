## 一、更换图片 / 视频素材

任务卡片的 4 个状态各对应一个素材文件：

| 状态 | 素材类型 | 文件位置 | 格式要求 |
|------|----------|----------|----------|
| Intro（接受任务） | 图片 | `Assets/Resources/Sprites/task.png` | PNG（当前 605×411） |
| Working（破解中） | 视频 | `Assets/StreamingAssets/TaskVideos/working.mp4` | H.264/AAC（avc1） |
| Success（✓ 通过） | 视频 | `Assets/StreamingAssets/TaskVideos/success.mp4` | H.264/AAC（avc1） |
| Fail（× 失败） | 视频 | `Assets/StreamingAssets/TaskVideos/fail.mp4` | H.264/AAC（avc1） |

### 1. 换 Intro 图片

直接替换 `Assets/Resources/Sprites/task.png`（**保持文件名**），Unity 自动导入，进 Play 即生效。
- 图片**必须放在 `Resources/`**：`Resources.Load` 是**同步**加载，WebGL 也随 Build 打包进产物，无需异步，不会引入"图片加载中"的中间态。
- 缺图不崩：自动回退纯色 + 「接受任务」文字。
- 视频素材则**必须放 `StreamingAssets/`**（VideoPlayer 加载机制要求，Editor/Standalone 读本地文件、WebGL 读相对 URL）。**两者加载机制不同，所以分开存放是刻意的**——不建议为了"放一起"而把图片挪进 StreamingAssets（WebGL 上图片只能异步 `UnityWebRequest` 加载，Intro 第一次会出现图片没就绪的中间态，正是本项目要避免的）。

### 2. 换任务视频

把新视频命名为 `working.mp4` / `success.mp4` / `fail.mp4`，替换 `Assets/StreamingAssets/TaskVideos/` 下的同名文件。编辑器进 Play 即生效；**WebGL 需重新导出 Build**。

- **格式硬性要求：H.264/AAC（编码标记 `avc1`）**。浏览器 `<video>` 只认 H.264/VP8/VP9/AV1/HEVC；如果视频是 `mp4v`（MPEG-4 Part 2，老的 DivX/Xvid 那类），编辑器能放但**浏览器解不出视频帧 → 一直显示占位图**。
- **检查编码**（无需 ffmpeg）：
  ```bash
  grep -aoE 'avc1|mp4v' 你的视频.mp4
  ```
  输出含 `mp4v` 就说明要转码。
- **转码**（Windows 自带 Media Foundation，无需安装任何东西），脚本在 `\WildernessReplay\_transcode.ps1`：
  ```bash
  powershell -File D:\work\WildernessReplay\_transcode.ps1 -Dir <视频所在目录> -Targets working.mp4,success.mp4,fail.mp4
  ```
  会在同目录生成 `*_h264.mp4`，用它们替换正式文件即可（保留原尺寸/时长，只换编码）。
- 视频时长建议与状态匹配：Working 可循环（任意时长，跟回合走）；Success/Fail 会**从头完整播一遍再淡出**，卡片显示时长=视频时长，所以结果视频多长它就显示多长。

## 二、当前实现

### 1. 卡片 4 态（数据驱动）

`TaskBadgeManager` 每帧读 `player.data.rounds[cur-1].teams[].task`，与 `rounds[cur-2]`（数据里的上一回合）做跳变检测，判定状态并创建/更新/销毁卡片：

| 状态 | 表现 | 触发（上一回合 → 当前回合） |
|------|------|------|
| Intro | task.png 图片（至少展示 2 回合） | 有任务且 `roundCost == 0`（刚接任务那回合） |
| Working | working.mp4 循环播放 | 有任务未完成（稳态） |
| Success | success.mp4 从头播一遍后淡出销毁 | 上一回合有任务未完成 → 本回合 `isTaskComplete` |
| Fail | fail.mp4 从头播一遍后淡出销毁 | 上一回合有任务未完成 → 本回合任务消失且未完成 |

- 结果态（Success/Fail）播放中**不受稳态 Hidden 打断**，只有新任务（Intro/Working）能打断；播完淡出后由管理器销毁。
- 拖动进度条 / JumpTo：先全清卡片，再按目标回合数据重建（杜绝"开拓者站着却残留结果框"）。

### 2. 渲染层（无中间态）

- **Intro**：底板 `_MainTex` ← `Resources.Load("Sprites/task")`（图片自带「接受任务」字样，不叠文字）。
- **Working**：底板 `_MainTex` ← **全局共享 working 视频 RT**。`TaskBadgeManager.EnsureSharedVideo` 在游戏开始即 Prepare + 循环播放进共享 RenderTexture，Working 态立即可显示，无需等卡片各自准备。
- **Success / Fail**：底板 `_MainTex` ← **卡片自有播放器**。`Awake` 后台 Prepare success/fail；结果到来时 `isLooping=false` + `time=0` **从头播一遍**，`_resultDuration = 视频时长`，播完淡出销毁。
  - 不用共享循环 RT 的原因：共享播放器一直在循环，`VideoPlayer.time=0` 的 seek 在播放中是**延迟生效**的，卡片切过去会先显示旧位置画面（若恰好靠近开头，表现为"开头 ~1s 被播两遍"）。
- **无中间态核心**：目标视频未就绪时保持当前画面（Intro 图 / working 视频）不动，渲染出帧后无缝接管；绝不出现蓝/白/空加载底。
- 视频加载失败：降级纯色 + 文字（Working 蓝「破解中」/ Success 绿「✓ 通过」/ Fail 红「× 失败」）。

### 3. 关键设计

- **外观**：`CARD_SCALE=4`（2 倍放大，底板 4×2.4）；金黄描边（Border `#FFD700`），淡入淡出随背景同步（不会残留黄框）。
- **暂停冻结**：回放暂停时动画计时与所有视频同步冻结（共享播放器由管理器统一 Pause/Play，卡片自有播放器由卡片 Update 处理）。
- **定位**：锚点以开拓者血条上方 +0.5 净空计算，不受父节点缩放影响。
- **性能**：底板/描边共享一个 `Sprites/Default` 材质 + MaterialPropertyBlock 改色 + GPU Instancing。

### 4. WebGL 关键点

- **URL**：`TaskCardBadge.VideoUrl()` 生成相对正斜杠路径（剥 `http(s)://host`，协议跟随当前页）。**勿用 `Path.Combine`**（Windows 会拼出反斜杠，浏览器 `<video>` 无法播放）。
- **编码**：视频必须 H.264/avc1（见第一节），否则浏览器解不出帧。
- **autoplay**：所有任务视频 `audioOutputMode = VideoAudioOutputMode.None`（静音 → 浏览器 autoplay 策略才放行）。
- **就绪**：WebGL 上 `prepareCompleted` 回调可能不触发，用 `isPrepared` 轮询兜底。
- **测试**：用 HTTP 服务器打开构建（`python -m http.server` / `npx http-server` / Unity Build & Run），勿 `file://` 双击。
