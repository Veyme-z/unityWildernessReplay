# 夜间机器人数量卡顿优化 — 实现记录

> 日期：2026-08-20
> 目标：夜晚机器人数量 80~156 只时画面卡顿，**保留机器人数量**，只做性能优化。
> 结论：✅ 修复。夜间播放 CPU 主线程 11.2ms → 0.05ms，无 1s 级卡顿尖峰，帧时 ~12ms（≈83fps）。
> 相关文档：[PROJECT_STATE.md](PROJECT_STATE.md)「近期改动」2026-08-20 条目。

## 一、问题背景（实测定位）

白天不卡，夜晚机器人到 80~100+（峰值第 861 回合 **156 只**）时画面明显卡顿，要求保留数量只做优化。

Play 模式第 861 回合实测：

| 指标 | 数值 | 说明 |
|---|---|---|
| 活跃 Animator | **164** | 156 只野兽各 1 + 其他单位，每帧逐体算动画 → CPU |
| 活跃 SkinnedMeshRenderer | **214** | 156 只野兽各 1 + 其他单位，蒙皮无法 GPU 实例化 → GPU |
| 日志面板 CPU | **11.2ms** | 每回合 156 条移动日志 × 全量 Text 重排 + `ForceUpdateCanvases` → 1s+ 尖峰 |
| 机器人相关 DrawCall | ~312 | 156 蒙皮 + 156 独立材质血条 |

**关键结论：机器人渲染（Animator/蒙皮）与事件日志面板造成**——机器人越多 → 移动日志越多 → 面板逐条全量重排。

## 三、UnitView.cs — 野兽距离 LOD

### 3.1 新增字段

```csharp
// ── 野兽距离 LOD（远处降级为静态烘焙网格 + GPU 实例化，省 Animator CPU 与蒙皮 GPU） ──
SkinnedMeshRenderer _skinned;   // 野兽 Robot 的活跃蒙皮渲染器
GameObject _lodGo;              // 远处静态网格宿主
bool _lodStatic;                // 当前是否处于静态 LOD 态
const float LOD_RANGE = 30f;    // 相机 XZ 水平距离阈值（随相机平移/缩放自然响应；可调）
static readonly Dictionary<int, Mesh> s_lodMeshCache = new Dictionary<int, Mesh>(); // 每类型共享一份烘焙网格
static Camera s_camera;         // 复用 Camera.main 缓存
```

### 3.2 ConfigureFromBeastPrefab 挂钩

取野兽 Robot 的**活跃**蒙皮渲染器（`false` 排除 inactive 的 Skeleton 幽灵件）：

```csharp
// 距离 LOD：仅野兽启用；(false) 排除 inactive 的 Skeleton 幽灵件，取活跃 Robot 蒙皮
_skinned = GetComponentInChildren<SkinnedMeshRenderer>(false);
```

### 3.3 LateUpdate 末尾 LOD 判定

按**相机 XZ 水平距离**两档切换（相机高度 40 固定不参与，平移/缩放时响应自然）；**滞回区间**防边界来回切换闪烁：

```csharp
if (_skinned != null && _animator != null)
{
    if (s_camera == null) s_camera = Camera.main;
    if (s_camera != null)
    {
        Vector3 camPos = s_camera.transform.position;
        Vector3 delta = new Vector3(camPos.x - transform.position.x, 0f, camPos.z - transform.position.z);
        float d2 = delta.sqrMagnitude;
        // 静态化用 LOD_RANGE，恢复动画用 0.85*LOD_RANGE（滞回）
        bool far = _lodStatic
            ? d2 >= LOD_RANGE * 0.85f * LOD_RANGE * 0.85f
            : d2 >= LOD_RANGE * LOD_RANGE;
        if (far != _lodStatic) SetLodStatic(far);
    }
}
```

### 3.4 SetLodStatic — 静态化核心

- **每野兽类型只烘焙一次**共享静态网格（4 类型 = 4 网格），姿势取「第一只进入远处的野兽当时的姿势」；
- 静态网格改由 `MeshRenderer` 渲染，材质开 `enableInstancing` → 远处同类型机器人 GPU 实例化；
- **禁用 Animator + SkinnedMeshRenderer**（省动画 CPU + 蒙皮 GPU）；
- 挂到 Robot 节点下、零偏移，`localScale` 补偿回 `1/lossyScale`（见「关键坑」）。

```csharp
void SetLodStatic(bool toStatic)
{
    _lodStatic = toStatic;
    if (toStatic)
    {
        var mat = _skinned.sharedMaterial;
        if (mat != null) mat.enableInstancing = true;

        Mesh sharedMesh;
        if (!s_lodMeshCache.TryGetValue(state.type, out sharedMesh) || sharedMesh == null)
        {
            sharedMesh = new Mesh();
            _skinned.BakeMesh(sharedMesh);
            s_lodMeshCache[state.type] = sharedMesh;
        }

        if (_lodGo == null)
        {
            _lodGo = new GameObject("LodMesh");
            _lodGo.transform.SetParent(_skinned.transform, false);
            var mf = _lodGo.AddComponent<MeshFilter>();
            mf.sharedMesh = sharedMesh;
            var mr = _lodGo.AddComponent<MeshRenderer>();
            mr.sharedMaterials = _skinned.sharedMaterials;
            mr.shadowCastingMode = UnityEngine.Rendering.ShadowCastingMode.Off;
            mr.receiveShadows = false;
        }
        // BakeMesh 烘焙在「除以渲染器 lossyScale」的世界比例空间：必须把 LOD 渲染器 lossyScale 补偿回 1
        var lossy = _skinned.transform.lossyScale;
        _lodGo.transform.localScale = new Vector3(
            lossy.x > 0.0001f ? 1f / lossy.x : 1f,
            lossy.y > 0.0001f ? 1f / lossy.y : 1f,
            lossy.z > 0.0001f ? 1f / lossy.z : 1f);
        _lodGo.SetActive(true);
        _skinned.enabled = false;
        _animator.enabled = false;
    }
    else
    {
        _skinned.enabled = true;
        _animator.enabled = true;
        if (_lodGo != null) _lodGo.SetActive(false);
    }
}
```

### 3.5 血条材质共享实例化

原 `CreateHpCube` 每只野兽 `new Material(Standard)` → 156 血条 = 156 个独立材质、无法合批。改为全局共享一个材质 + `enableInstancing`，血条颜色仍由每体 `MaterialPropertyBlock` 提供：

```csharp
static Material s_hpFillMat;
static Material GetSharedHpFillMat()
{
    if (s_hpFillMat == null)
    {
        s_hpFillMat = new Material(Shader.Find("Standard"));
        s_hpFillMat.color = new Color(0.267f, 0.925f, 0.435f);
        s_hpFillMat.SetFloat("_Metallic", 0f);
        s_hpFillMat.SetFloat("_Glossiness", 0.2f);
        s_hpFillMat.enableInstancing = true;
    }
    return s_hpFillMat;
}
```

`CreateHpCube` 中 `rend.sharedMaterial = GetSharedHpFillMat();`（替换 `new Material(...)`）。

## 四、EventLogPanelController.cs — 日志面板批量刷新

### 4.1 原实现（卡顿根源）

每加一条日志就做全量 Text 赋值 + 强制整画布重排：

```csharp
public void AddEventLog(string message, string category)
{
    // ...append 到 _sb（上限 8000 字符）...
    _text.text = _sb.ToString();          // 全量重排
    Canvas.ForceUpdateCanvases();         // 强制整画布布局更新
    if (_scroll != null) _scroll.verticalNormalizedPosition = 0f;
}
```

夜间每回合 156 只野兽移动 → StateEngine 生成 150+ 条「移动」日志 → **单帧内重排上百次** → 1s+ 卡顿尖峰。

### 4.2 修改后（每帧批量刷新一次）

`AddEventLog` 只追加 + 标记脏；`LateUpdate` 统一刷新一次：

```csharp
bool _dirty;

public void AddEventLog(string message, string category)
{
    // ...append 到 _sb（上限 8000 字符，不变）...
    _dirty = true;   // 仅标记，不再逐条重排
}

void LateUpdate()
{
    if (!_dirty || _text == null) return;
    _dirty = false;
    _text.text = _sb.ToString();
    Canvas.ForceUpdateCanvases();
    if (_scroll != null) _scroll.verticalNormalizedPosition = 0f;
}
```

日志内容与滚底功能**完全保留**，只是把一帧内上百次重排合并为 1 次。

### 3.6 远处静态机器人轻微待机浮动

LOD 静态机器人是**冻结姿势**，远处看起来像死板雕像。`UnitView.LateUpdate` 在 LOD 块中给静态 `LodMesh` 加**呼吸式待机浮动**（上下浮动 + 缩放摆动），每只按 `state.id` 错开相位；暂停时冻结。成本 ≈ 每只 2 次 `Sin`，实测 CPU 增量 **0.09ms → 0.09ms（可忽略）**：

```csharp
if (_lodStatic && _lodGo != null)
{
    bool replayPlaying = _player == null || _player.playing;
    if (replayPlaying)
    {
        float ph = (float)(state.id % 997) * 0.618f;   // 每只错开相位
        float t = Time.time % 100f;                    // 包裹避免大数精度问题
        float bob = Mathf.Sin(t * 2.4f + ph) * 0.03f;  // 上下浮动
        _lodGo.transform.localPosition = new Vector3(0f, bob, 0f);
        float s = 1f + Mathf.Sin(t * 1.8f + ph * 1.3f) * 0.012f; // 呼吸缩放
        _lodGo.transform.localScale = new Vector3(_lodBaseScale.x * s, _lodBaseScale.y * s, _lodBaseScale.z * s);
    }
    else
    {
        _lodGo.transform.localPosition = Vector3.zero;
        _lodGo.transform.localScale = _lodBaseScale;
    }
}
```

`_lodBaseScale` 在 `SetLodStatic(true)` 记录补偿后的基准缩放（1/lossyScale），浮动在其上叠加。

### 3.7 远处野兽攻击/死亡时临时恢复动画（瞬态动画）

远处静态野兽只有待机浮动仍显"动作停止"。当野兽**造成伤害**（`TriggerAttack`，ReplayPlayer.OnDamage 触发）或**死亡**（`TriggerDeath`）时，临时恢复骨骼动画播放动作，随后自动回静态。为限制并发动画数（否则夜间上百只同时攻击 → CPU 回升，实测跳转后 101/140 远处野兽全部动画），加**冷却 2.5s + 窗口 1.0s**（占空比 ~40%）：

```csharp
public void TriggerAttack()
{
    if (_lodStatic && _skinned != null && Time.time - _lastTransientEnter > 2.5f)
    {
        _lastTransientEnter = Time.time;
        _transientAnimUntil = Time.time + 1f;
        SetLodStatic(false);   // 临时恢复 skinned + Animator
    }
    if (_animator == null) return;
    ...SetTrigger("onAttack")...
}

// LateUpdate LOD 判定里：
bool far = ...;
if (far && Time.time < _transientAnimUntil) far = false;  // 瞬态窗口内保持动画
if (far != _lodStatic) SetLodStatic(far);
```

## 五、关键坑（改动此功能务必读）

1. **`BakeMesh` 烘焙在「除以渲染器 lossyScale」的世界比例空间**：`BakeMesh(mesh)` 出的顶点 = 原始网格顶点 × 渲染器 lossyScale。因此 LOD 静态网格若直接挂在 Robot 下渲染，会在野兽根节点缩放（如 0.4）下被**再次缩小 1/0.4≈2.5 倍** → 机器人变小。必须把 LOD 网格 `localScale` 补偿回 `1/lossyScale`。

2. **绝不能除以 `state.animScale` 做归一化**：野兽 prefab 的 "Body" 节点是**空节点、不在 Robot 变换链里**，`animScale`（出生 0→1）**不影响 Robot 的 lossyScale**。若在出生瞬间转静态时用 `1/(lossy/animScale)`，animScale≈0.07 会把补偿放大成 0.18/0.117 的极小网格 → 远处机器人隐形。修复：直接用 `1/lossyScale`。

3. **`GetComponentInChildren<SkinnedMeshRenderer>(false)`**：野兽 prefab 内有 9 个 Skeleton 幽灵蒙皮件（inactive，零开销勿删），必须传 `false` 排除 inactive 才能取到活跃的 Robot 蒙皮。

4. **滞回区间**：静态化阈值 `LOD_RANGE`、恢复动画 `0.85×LOD_RANGE`，否则停在边界附近的野兽每帧来回切换（闪烁 + 无效开销）。

5. **`enableInstancing` 对蒙皮渲染器无害**：材质开实例化后 SkinnedMeshRenderer 不实例化但仍正常渲染，无副作用。

6. **日志面板的 `Canvas.ForceUpdateCanvases()` 极贵**：任何「逐条刷新 UI 文本 + 强制布局」的循环都要警惕。

## 八、参数调优指南（想让远处机器人更「活」）

全部参数都在 `Assets/Scripts/Scene/UnitView.cs` 顶部，是 **`public static float`**，**运行时可直接改值**（Unity 编辑器里用 execute_code 设值即可，无需重编译），改动立即生效。

| 参数 | 默认值 | 含义 | 想更「活」怎么调 | CPU 代价 |
|---|---|---|---|---|
| `LOD_RANGE` | `30f` | 野兽与相机 XZ 距离 ≥ 此值 → 静态；< 此值 → 完整骨骼动画 | 调大（40-50）→ 更多野兽动画 | ⚠️ 受相机位置影响大，居中相机下可能上百只同时动画 → CPU 回升。**不推荐作主调节** |
| `LodTransientCooldown` | `2.5f` | 远处野兽攻击瞬态动画的冷却秒数（每只每 N 秒最多临时动画一次） | **调小（1.0-1.5f）→ 攻击动作更频繁** | 每只动画野兽 ≈ 0.075ms CPU；调小 → 并发动画↑ |
| `LodTransientWindow` | `1f` | 每次攻击瞬态动画持续秒数 | 调大（1.5f）→ 动作更完整、更显眼 | 调大 → 更多野兽并发动画 |
| `LodIdleBobAmplitude` | `0.03f` | 静态机器人待机上下浮动幅度 | 调大（0.05-0.08f）→ 浮动更明显 | **≈0**（纯 2 次 Sin） |
| `LodIdleSwayAmplitude` | `0.012f` | 静态机器人待机缩放摆动幅度 | 调大（0.02-0.03f）→ 呼吸感更强 | **≈0** |

**CPU 预算参考**：每只动画野兽 ≈ 0.075ms 主线程。要稳定 60fps（16.7ms 预算），动画中的野兽数建议 **≤60 只**（≈4.5ms），再算上回合推进 Diff 的固有开销。

**推荐组合「明显恢复动作、兼顾性能」**：
```csharp
UnitView.LodTransientCooldown  = 1.2f;   // 攻击动作更频繁
UnitView.LodTransientWindow    = 1.2f;   // 动作更完整
UnitView.LodIdleBobAmplitude   = 0.05f;  // 待机浮动更明显
UnitView.LodIdleSwayAmplitude  = 0.02f;
UnitView.LOD_RANGE             = 30f;    // 保持 30（受相机影响，别动）
```
若 WebGL 上仍偏卡，把 `LodTransientCooldown` 回调到 `2.5~4f`。

## 一、问题定位

| CPU 满载发热 | 浏览器无限制渲染超高帧率 | 未锁帧 + 垂直同步未关，跑满浏览器刷新/空闲渲染 |

## 四、UnitView.cs — 剥离无用物理组件

### 4.1 新增 StripPhysics

```csharp
/// <summary>纯数据驱动回放：销毁单位身上所有物理组件（碰撞体/刚体），关闭后台物理引擎计算开销。</summary>
void StripPhysics()
{
    foreach (var col in GetComponentsInChildren<Collider>(true)) { Object.Destroy(col); }
    foreach (var rb in GetComponentsInChildren<Rigidbody>(true)) { Object.Destroy(rb); }
}
```

`ConfigureFromBeastPrefab()` 与 `ConfigureFromUnitPrefab()` 开头各调用一次。

### 4.2 关键：防御塔视觉二次剥离

防御塔视觉包装（`SetupTowerVisual` 实例化的 `CubeTowers/Tower_*_Red/Blue` Prefab）是在 **`StripPhysics()` 之后**才实例化的，会重新带进 Minigun / BasePillar 等碰撞体。因此在 `ConfigureFromUnitPrefab()` 末尾、`SetHp` 之后**二次调用** `StripPhysics()` 兜底：

```csharp
SetHp(state.hp, state.maxHp);
StripPhysics(); // 二次剥离：防御塔视觉包装是此时才实例化的，内部自带碰撞体需一并销毁
```

## 五、SceneBuilder.cs — 地形静态批处理 + NPC 物理剥离

### 5.1 草地瓦片静态标记（按任务要求）

Prefab 分支与 Cube 回退分支均标记静态；碎草容器同样标记：

```csharp
var tile = Object.Instantiate(grassPrefab, pos, Quaternion.identity, grassRoot);
tile.name = "Grass_" + x + "_" + z;
tile.isStatic = true; // 静态标记：供 StaticBatchingUtility.Combine 运行时静态合批
```

### 5.2 关键：运行时静态合批（isStatic 标记本身不够）

草地瓦片是**运行时生成**的，`isStatic = true` **不会**让 WebGL 打包时自动合并（静态合批只针对打包时场景里已存在的静态物体）。必须用 `StaticBatchingUtility.Combine` 在生成后手动合批：

```csharp
// 生成完草格后调用：
StaticBatchGrass(grassRoot);

/// <summary>运行时静态合批：把 grassRoot 下所有子物体合并为少量静态网格，大幅降低 Draw Call。</summary>
static void StaticBatchGrass(Transform grassRoot)
{
    int n = grassRoot.childCount;
    if (n == 0) return;
    var gos = new GameObject[n];
    for (int i = 0; i < n; i++) gos[i] = grassRoot.GetChild(i).gameObject;
    StaticBatchingUtility.Combine(gos, grassRoot.gameObject);
}
```

### 5.3 中立 NPC 物理剥离

中立 NPC（任务官/小贩/武器店）是 `SceneBuilder.BuildNeutralNpc` **直接实例化、不走 UnitView** 的，需在原文件内单独剥离：

```csharp
var go = Object.Instantiate(npcPrefab, root);
go.name = "NPC_" + t + "_" + x + "_" + y;
// 纯数据驱动回放：NPC 是静态单位装饰，销毁物理组件关闭物理引擎开销
foreach (var col in go.GetComponentsInChildren<Collider>(true)) Object.Destroy(col);
foreach (var rb in go.GetComponentsInChildren<Rigidbody>(true)) Object.Destroy(rb);
```

## 七、关键坑（改动此功能务必读）

1. **运行时生成的静态物体，`isStatic` 标记不会触发打包时静态合批**：Unity 的静态合批（Static Batching）在**打包阶段**处理场景里已存在的 `isStatic` 物体；`SceneBuilder` 是运行时实例化草格的，必须补 `StaticBatchingUtility.Combine` 才会真正合批。只加 `isStatic` 而不 `Combine` = Draw Call 不变。

2. **`Combine` 之后不要再去改子物体 Transform**：静态合批把子网格烘焙进合并网格后，子物体位置被归零吸收。草格是纯静态地形、从不移动，所以安全；若未来要给草格做动画/移动，必须排除出合批范围。

3. **塔视觉是 `StripPhysics()` 之后才实例化的**：`SetupTowerVisual` 在 `ConfigureFromUnitPrefab` 中晚于开头的 `StripPhysics()` 执行，会重新带进碰撞体。漏了二次剥离 → 每座塔残留 Minigun/BasePillar 碰撞体。

4. **中立 NPC 不走 UnitView 创建链**：直接由 `SceneBuilder` 实例化，不会命中 `UnitView.StripPhysics`，需单独处理。

5. **本项目代码不用物理射线拾取**：单位交互走 `Pickable` 标记（纯 C# 引用），相机用数学 `Plane.Raycast`（非 Collider 射线），因此剥离所有碰撞体不影响任何玩法/交互。
