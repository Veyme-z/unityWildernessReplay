## 一、当前：K151 装甲车 + 宝箱适配 Built-in（2026-08-31）

### 问题现象
- `Assets/gr.desert/Korean Army Light Tactical Vehicle/Prefab/Prefab_K151_WoodLand01.prefab` 在工程里**整辆粉紫**。
- `Assets/Sat Productions/B-01/Free Treasure Chest/Prefabs/Gold Chest.prefab` 需一并放入 Resources 作为未来任务点（宝箱本身材质正常，仅需放置）。

### 根因（三层，`gr.desert` 包引用链全部失效）
1. **URP shader 缺失**：车辆 4 个 `.mat` 引用 shader GUID `933532a4fcc9baf4fa0491de14d08ed7`（URP Lit），Built-in RP 工程里该 GUID 不存在 → shader 缺失。
2. **贴图 GUID 全错位**：`.mat` 里 `_BaseMap`/`_BumpMap`/`_MetallicGlossMap` 等引用的贴图 GUID 与实际贴图文件 GUID **全部对不上**（`GUIDToAssetPath` 全部 MISSING）——资源包打包时内部引用错位。
3. **FBX `externalObjects` 材质 remap 失效**：`Mesh_K151_WoodLand01.fbx` 用 `materialImportMode=2`（ImportStandard）+ `materialLocation=1`（UseExternalMaterials），其 `externalObjects` remap 的 4 个 `second` GUID 全部指向不存在的资产 → FBX 子 prefab 的 **21 个 MeshRenderer 材质槽全 NULL**（Unity 对 NULL 槽渲染为粉紫）。

> **诊断线索**：`sharedMaterials` 返回 `[NULL]`（而非「有材质但 shader 缺失」）＝ remap 引用坏了；shader 缺失但材质对象在 ＝ `Material.GetTexture()` 返回 null（序列化纹理引用仍在，只是 API 走 shader 查不到）。

### 解决方案（对齐防御塔 URP→Built-in 先例）
1. **按文件名找真实贴图**：`AssetDatabase.FindAssets("K151_Texture_CarBody_BaseColor")`（不能用坏 GUID）。
2. **新建 4 个 Standard 材质** 到 `Assets/ProjectAssets/KoreanArmyK151_BuiltIn/Materials/`：
   - `K151_CarBody / K151_CarAccessory / K151_Glass / K151_Inside`
   - albedo→`_MainTex`、normal→`_BumpMap`、height→`_ParallaxMap`（`_Parallax` 0.005，玻璃 0.016）
   - **金属度+粗糙度打包**：读 metallic R + roughness R（`smooth = 1 - roughness`）合成 `_MetalSmooth.png`（R=金属度、A=光滑度）作 `_MetallicGlossMap`（`sRGBTexture=false`）
   - 玻璃：`_Mode=3` 透明（SrcBlend=1 / DstBlend=10 / ZWrite=0 / renderQueue 3000）+ `_EmissionMap` 发光
3. **修复 FBX 材质槽**：`AssetImporter.AddRemap(new SourceAssetIdentifier(typeof(Material), "Texture_CarBody"), mat)`，8 个槽（`Texture_CarAccessory/Body/Glass/Inside` + `Material #67/68/78/79`）→ `SaveAndReimport()`。源 prefab 与演示场景同步恢复。
4. **生成包装 prefab** 到 `Assets/Resources/Prefabs/`（根节点未来挂任务点逻辑 + `Model` 子节点嵌套源模型）：
   - `K151ArmoredVehicle.prefab`（约 2.7×2.55×5.3m，木林迷彩，origin 居中贴地）
   - `GoldChest.prefab`（金宝箱含 LOD，约 0.82×0.29×0.56m）

### 验证
- 渲染截图逐像素检查：**0 粉红（magenta）像素**、0 空材质、全部 Standard shader。
- 车辆 renderer 槽位解析正确：Body→CarBody/Inside/Glass、车窗→Glass、雨刮→Accessory 等。

### 本次排查的关键坑
| 坑 | 说明 |
|----|------|
| `Material.GetTexture()` 在 shader 缺失时返回 **null** | 读 URP 旧材质的贴图不能走 `GetTexture`，须 `AssetDatabase.FindAssets` 按文件名找，或用 SerializedObject 读 `m_SavedProperties.m_TexEnvs` |
| FBX 材质 remap 的正确改法 | SerializedObject 里 `m_Materials` 数组元素只有 `type/assembly/name`（`externalObjects` 的 first 部分被拍平），**直接 `FindPropertyRelative("second")` 会 NRE**；用公共 API `AssetImporter.AddRemap(SourceAssetIdentifier, obj)` / `RemoveRemap` / `GetExternalObjectMap()` |
| 贴图 `GetPixels` 抛 "texture data is not readable" | 须先 `(AssetImporter.GetAtPath(...) as TextureImporter).isReadable = true` + `SaveAndReimport()` 再读，读完恢复 `isReadable=false`；`SerializedObject.FindProperty("isReadable")` 返回 null（须用强类型 API） |
| 重导入后贴图引用失效 | `SaveAndReimport` 后原 `Texture2D` 引用失效，须 `AssetDatabase.LoadAssetAtPath` 重新加载再 `GetPixels` |

## 二、历史：URP 素材转 Built-in RP（防御塔 CubeTowerDefense）

- **问题**：`Assets/CubeTowerDefense/` 是 URP 专用素材，Built-in RP 工程里显示粉紫。
- **方案**：**不改 URP 源素材**。在 `Assets/ProjectAssets/CubeTowerDefense_BuiltIn/` 建镜像（`Materials/` 全部 Standard 材质 + `Resources/Prefabs/Towers/` 源塔），再在 `Resources/Prefabs/Buildings/CubeTowers/` 生成 6 个可编辑**视觉包装 prefab**（嵌套引用源塔，不复制 FBX/贴图），根上挂 `TowerVisualController`。一键重建工具：`Assets/Editor/TowerPrefabBuilder.cs`（菜单 `Tools/WildernessReplay/Build Tower Visual Prefabs`）。
- **约定**：第三方 URP 源素材「勿改」，转换产物一律放 `ProjectAssets/*_BuiltIn/`；运行时加载的包装 prefab 放 Resources。
